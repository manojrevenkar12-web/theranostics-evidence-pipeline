# theranostics-evidence-pipeline

An auditable data pipeline for PSMA-PET/CT studies, from the DICOM a hospital sends to the evidence a regulatory
submission needs. It reads each site's PET series, refuses values it cannot trust and asks the site to fix them,
computes SUV correctly under each site's decay convention, links the same patient across hospitals, de-identifies
headers and documents, quantifies tumour burden and RECIP 1.0 response, builds a temporal knowledge graph from
reports and therapy letters with a language model whose every fact is checked by code, predicts PSA50 response
with an explained model, and seals the results in an evidence pack where every number traces back to source files.

```
site drops (DICOM)      rules ──► refuse + query the site ──► answer ──► re-check
      │                   │
      ▼                   ▼
 de-identify ──► volume + NIfTI ──► SUVbw ──► calibration check (liver reference) ──► lesions, PSMA-TV, RECIP
                                                                                            │
 reports, letters ──► de-identify ──► reader proposes facts ──► code checks ──► temporal knowledge graph
                                                                                            │
                                  response model (leave-site-out, SHAP) ◄───────────────────┘
                                                  │
                     evidence pack: plan, endpoints, inventory, model card, lineage, sealed manifest
```

## Results

The pipeline runs on a simulated multi-site cohort that holds the truth it cannot see: each patient's lesions,
their true SUV, the therapy response, and how each hospital's data goes wrong. Every design reads the same drops,
the same documents and gets the same answers from the sites.

## What each safeguard does

| Safeguard | The failure it stops | How |
|---|---|---|
| Unit rules | A weight entered in grams or a dose in MBq makes SUV off by 1,000 or 1,000,000 | Plausible ranges per tracer; outside them the series is refused and the site is asked. Nothing is guessed. |
| Decay reference | Sites that decay-correct images to injection time (`DecayCorrection = ADMIN`) get SUV inflated by about 1.8 for Ga-68 if the dose is decayed again | The dose is decayed to scan start only when the image is corrected to scan start |
| Timing rule | A clock or time-zone error puts the injection after the scan | Uptake time must be 30–240 min |
| Slice rules | Instance numbers that run against position flip the body; a missing slice shifts everything above it | Slices ordered by position along the slice normal; spacing checked; a gap is refused and a re-send requested |
| De-duplication | A re-sent series counted as a second scan | Instances keyed by SOP Instance UID |
| Linkage | A patient referred to another hospital becomes two people, so baseline and follow-up never meet | Keyed pseudonym from the normalised name (MÜLLER = MUELLER) and birth date |
| Calibration check | A scanner reading 16% high shifts every SUV at that site | Median liver SUV per site against the other sites; a deviation over 8% triggers a query for the phantom cross-calibration factor; without an answer the site is left out of quantitative endpoints |
| Site queries | Refused series are lost | A letter per series, in the site's language, naming each problem and the fix; checked to carry no name, ID or birth date |
| Fact checks | A language model invents a sentence, misreads a number or picks the wrong code | A fact is kept only if its sentence is in the document, its date and number are in that sentence, and the sentence names the coded term |
| Term induction | New terms (a newer therapy agent, the miPSMA score) are missed, or typos become ontology terms | A term the vocabulary lacks is admitted after 3 documents from 2 sites, unless it is one edit away from a known word |
| De-identification | Names, IDs and birth dates leave in headers, private tags, free-text comments and report headers | An allowlist of header fields; keyed pseudonyms; per-patient date shifts in headers and text; new UIDs |

## The reader and the knowledge graph

Reports and therapy letters arrive in English or German. A reader (a language model in production, a simulator
with configured error rates in the lab) proposes facts as JSON: kind, code, date, value and the exact sentence.
Code keeps a fact only when the sentence, date, number and code all check out, and records the sentence's hash as
its source. Accepted facts and the imaging findings form a temporal knowledge graph per patient (scans, findings,
therapy cycles, PSA), which flags findings reported but not imaged and the reverse. `ClaudeReader` uses the same
interface and the same checks; it is not run in CI.

## Run it

```bash
pip install -e ".[dev]"
pytest                          # unit tests and a small end-to-end world
tep lab dev                     # all designs on the dev sites: reports/dev.json, REPORT.md, this README, the dashboard data, evidence/dev
tep lab gate dev                # fails if a gate fails
tep evidence verify dev         # checks every file of the evidence pack against its sealed manifest
tep ingest DROP_DIR OUT_DIR     # production path: de-identified SUV NIfTI + sidecars, data queries, quality, lineage
cd web && npm ci && npm run dev # dashboard
```

`tep lab heldout` runs four held-out sites once; it writes `reports/heldout.lock` first and refuses to run again.

| `src/tep/lineage` | Content-addressed lineage and trace |

| `infra/gcp` | Terraform: buckets with retention, BigQuery dataset, Cloud Run job, least-privilege service account |

## Limits

- **The cohort is simulated.** Patients, lesions, uptake, response and every site defect are drawn from
  assumptions in `config/world.json`, not from clinical data. The numbers compare designs on the same data; they
  are not a clinical validation of the segmentation or the model.
- **Images are coarse.** 48 × 48 × 32 voxels of 5 mm, spheres and ellipsoids, Gaussian blur and noise. Real
  PSMA-PET has partial-volume effects, motion, and physiological uptake the atlas here does not model.
- **The reference standard is the simulator's truth**, not expert readers. Reader variability is not modelled.
- **The language model is simulated in the lab.** `ClaudeReader` exists and is tested against a stub only.
- **GCP is declared, not deployed.** The Terraform validates in CI; nothing has run on Google Cloud.
- **The evidence pack is a structure for audit, not a regulatory submission.** It follows the idea of
  traceable, pre-specified analysis; it has not been reviewed against any regulator's requirements.
- **This is a portfolio project.** DICOM, NIfTI and medical-imaging statistics here are my own work, not yet done at an employer.
